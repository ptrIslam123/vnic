# Архитектура аппаратной эмуляции NIC

Данный документ описывает архитектурный подход к программной эмуляции сетевой карты (NIC), максимально приближенной к поведению реального оборудования. Цель - создать библиотеку, которая воспроизводит работу NIC на уровне, достаточном для качественного тестирования и разработки сетевых приложений, при этом сохраняя высокую производительность, сопоставимую с аппаратными решениями.

---

## Ключевые принципы

### 1. Минимизация копирований данных

Одно из фундаментальных требований - **минимизировать количество копирований пакетов**. Каждое копирование — это дополнительная нагрузка на CPU, шину памяти и кэш. Дальше все операции производятся через указатели.

### 2. Разделение на дескрипторы и буферы

Пакет не хранится как единый объект. Вместо этого вводятся **две сущности**:

- **Дескриптор пакета (PacketDescriptor)** - метаданные пакета: ссылка на буфер, длина, временная метка, флаги оффлоадов, номер очереди. Имеет фиксированный размер.
- **Буфер пакета (PacketBuffer)** - область памяти, в которой хранится полезная нагрузка (payload). Имеет фиксированный размер.

**Зачем это нужно:**
- Фиксированные размеры буферов упрощают управление памятью.
- Пул буферов заранее выделяет память блоками фиксированного размера, что исключает фрагментацию.
- Дескрипторы и буферы живут в разных пулах и переиспользуются независимо.

### 3. Цепочки буферов для больших пакетов

Если сетевой пакет превышает размер одного буфера, выделяется несколько буферов, и они связываются в цепочку через поле `next`. Один дескриптор ссылается на первый буфер цепочки, а каждый следующий буфер указывает на следующий.

**Преимущества:**
- Нет копирования при разбиении на сегменты.
- Jumbo Frames и TSO обрабатываются естественным образом.
- Малые пакеты (64 байта) занимают ровно один буфер.

## Роль Link: физическая среда передачи

### Концепция

**Link** - это физическая среда (кабель, оптоволокно), которая передаёт **сигналы**, а не пакеты. В программной эмуляции Link — это **чистая труба для байтов**. Он не знает ни о пакетах, ни об IP, ни о TCP/UDP.

**Что делает Link (текущая реализация):**
- Передаёт байты между двумя точками — две in-memory очереди (RX и TX).
- Предоставляет методы `putRx()`/`takeRx()` и `putTx()`/`takeTx()`.
- Хранит состояние `up/down`: пока линк опущен, NIC не забирает данные.

### Метод takeRx()

`Link::takeRx(packet, timeout)` - читает сырые байты из RX-очереди Link. **Блокирующий** вызов с таймаутом: если данных нет, возвращает 0; иначе — массив байт пакета. Аналогично `takeTx()` для TX-очереди.

### Метод putRx() / putTx()

`Link::putRx(bytes)` / `Link::putTx(bytes)` - записывает сырые байты в соответствующую очередь Link. Используется для эмуляции передачи извне или для прямой подачи пакетов (например, в тестах).

## Роль NIC: устройство обработки

**NIC (Network Interface Card)** - это устройство, которое:
- Получает сырые байты из Link.
- Преобразует их в пакеты (дескрипторы + буферы).
- Вычисляет RSS-хэш.
- Определяет номер очереди через RETA.
- Помещает дескриптор в очередь.

 NIC сам опрашивает Link через метод `poll()`. Link не имеет фонового потока. NIC решает, когда забрать данные из Link.


### Метод poll()

`NIC::poll()` - циклический метод, который вызывается из основного цикла обработки.

**Что делает poll():**
1. Вызывает `link_.takeRx()` для получения сырых байтов.
2. Если байтов нет - цикл продолжается.
3. Парсит кадр (`Parser::parse`) и прогоняет проверки (`VNic::validate`).
4. Вычисляет RSS-хэш (для IP-кадров).
5. Определяет номер очереди через RETA.
6. Выделяет сегменты буфера и копирует payload — **единственное копирование**.
7. Помещает дескриптор в очередь.

---

## RSS и распределение по очередям

**RSS (Receive Side Scaling)** - технология, которая распределяет входящий трафик по нескольким очередям на основе хэша от полей пакета (IP-адреса, порты, протокол). Каждая очередь обслуживается своим ядром CPU, что позволяет параллельно обрабатывать трафик.

### Как RSS определяет NUMA-узел

1. RSS вычисляет хэш от 5-tuple (src IP, dst IP, src port, dst port, protocol).
2. Хэш используется как индекс в таблице RETA.
3. RETA возвращает номер очереди.
4. Каждая очередь привязана к определённому NUMA-узлу (через конфигурацию).
5. Буфер выделяется из пула этого NUMA-узла.

## Управление памятью

### Пул буферов

**MemoryPool** - это пул заранее выделенных буферов фиксированного размера. Все буферы выделяются один раз при инициализации, а затем переиспользуются.

**Зачем пул:**
- Исключает аллокацию памяти в горячем пути.
- Исключает фрагментацию памяти.
- Позволяет быстро выделять и освобождать буферы.

**Как это работает:**
- RSS определяет очередь.
- Очередь привязана к NUMA-узлу.
- Буфер выделяется из пула этого NUMA-узла.
- Дескриптор помещается в очередь.

**Результат:** все данные локальны для ядра, которое обрабатывает очередь.

**Цикл жизни буфера:**
1. Буфер выделяется из пула NUMA-узла очереди.
2. Данные копируются в буфер.
3. Дескриптор помещается в очередь.
4. Приложение забирает дескриптор.
5. Приложение обрабатывает данные.
6. Приложение возвращает дескриптор.
7. Буфер возвращается в свой пул.
8. Буфер снова доступен для выделения.

## Полный жизненный цикл пакета

### Приём (Rx)

1. **Link::takeRx()** — читает сырые байты из RX-очереди Link.
2. **VNic::poll()** — фоновый поток опрашивает Link.
3. **Parser::parse()** — разбирает Ethernet/VLAN/L3/L4.
4. **VNic::validate()** — проверки на приёме (размер, MAC, VLAN, IPv4 length/checksum).
5. **RSS** — вычисляет хэш от 5-tuple (IPv4/IPv6); для не-IP кадров хэш не считается.
6. **RETA** — определяет номер очереди (снимок под RCU).
7. **PacketDescriptor** — заполняются `timestamp`, `vlanId`, `hash`, `queueId`.
8. **RxQueue::put()** — выделяет сегменты буфера и копирует payload (единственное копирование).
9. **Приложение::rx()** — забирает дескрипторы из очереди.
10. **Приложение** — обрабатывает данные.
11. **Приложение::freeRx()** — возвращает дескрипторы и освобождает всю цепочку буферов.

### Передача (Tx)

1. **Приложение** — формирует цепочку `PacketBuffer` и `PacketDescriptor`.
2. **VNic::tx()** — передаёт дескрипторы в TX-очередь (возвращает число переданных).
3. **TxQueue::put()** — линеаризует цепочку в непрерывный буфер (одно копирование).
4. **Link::putTx()** — записывает байты в TX-очередь Link.
5. **Приёмная сторона::takeTx()** — читает байты из TX-очереди.
